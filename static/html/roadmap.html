1. Roadmap Overview

This roadmap defines the product evolution of Coin, a peer-to-peer token exchange on Solana where AI agents and humans trade tokens directly with each other. The roadmap spans from a bootstrapped 4-week MVP through a fully-funded product build, growth phase, scale infrastructure, and long-term ecosystem development across approximately 24 months.

Coin's development follows a two-stage approach: a 4-week bootstrapped MVP (near-zero cost using free-tier infrastructure) to demonstrate agent-to-agent P2P trading on Solana and secure funding, followed by a funded full build (estimated $200-350K) that takes the product from demo to public launch in approximately 12 additional weeks. After launch, the roadmap progresses through growth (V2), scale (V3), and ecosystem (V4+) phases, each gated by the success metrics of the prior phase.

Roadmap Philosophy: Every feature earns its place by solving a specific user problem or unblocking a specific growth bottleneck. Features in later versions are deliberately sequenced because their value depends on earlier infrastructure being in place. The team does not advance to the next phase until the current phase's success metrics are confirmed.

3. MVP Phase: Investor Demo (Weeks 1-4)

MVP -- Weeks 1-4 -- Near-Zero Cost

The single goal of the MVP is to demonstrate agent-to-agent P2P trading working on Solana -- real escrow-settled trades between AI agents, not a mockup. This is the fundraising asset. Investors need to see the core mechanism functioning: agents posting offers, agents accepting offers, atomic escrow settlement, Jupiter price reference, and the flywheel in action.

MVP Definition of Done: Two or more AI agents autonomously posting offers, accepting counterparty offers, and settling trades via Solana program escrow on mainnet with real funds. A web UI shows the activity live. A human can also accept an agent's offer. This is not a prototype or a mockup -- it is a working product demo.

Week 1 Escrow Program + Agent Wallets
  • Deploy escrow Anchor program on Solana devnet implementing the two-phase commit pattern: create_offer, accept_offer, cancel_offer
  • Create programmatic agent wallets (Solana keypairs) for 2-3 market-making agents
  • Integrate Jupiter aggregator API for SOL/USDC reference pricing
  • Fund agent wallets with devnet SOL and USDC via airdrop/faucet
  • Write integration tests confirming escrow lock, release, cancellation, and timeout flows
Milestone: Two wallets can escrow-settle a token swap on Solana devnet. Escrow PDA holds tokens and releases atomically on completion.
Week 2 Agent Runtime + Offer Engine
  • Build agent runtime in TypeScript: monitor Jupiter WebSocket price feeds, calculate spread, determine offer parameters
  • Implement offer creation flow: agent calls escrow program's create_offer with tokens locked in PDA
  • Implement offer acceptance flow: agent evaluates incoming offers against its auto-accept threshold and calls accept_offer
  • Deploy 2-3 Coin-operated agents quoting SOL/USDC on devnet at 0.05-0.1% below Jupiter prices
  • Agents trading with each other automatically -- posting offers, accepting counterparty offers, settling via escrow
  • Simple backend API (Next.js API routes + Convex) to store and query offers and completed trades
Milestone: Agents autonomously trading with each other on devnet. Offers posted, accepted, and settled without human intervention. All trades visible in Convex database.
Week 3 Web UI + Live Demo
  • Build minimal web app (Next.js on Vercel): marketplace feed showing live agent offers with price, quantity, and spread vs Jupiter
  • Display Jupiter reference price alongside each offer, calculated as "X% better than Jupiter" or "X% worse than Jupiter"
  • Real-time trade feed showing completed agent-to-agent trades as they settle
  • Basic wallet connection (Phantom browser extension) so a human visitor can accept an agent's offer and execute a trade
  • Trade detail view linking to Solana Explorer for on-chain verification of escrow settlement
Milestone: Web app showing live agent trading activity. A human can visit the site, connect Phantom, and execute a trade against an agent's offer with real escrow settlement.
Week 4 Polish + Mainnet Deploy + Investor Demo
  • UI polish: loading states, trade confirmation animations, error handling, mobile responsive layout
  • Deploy escrow program to Solana mainnet
  • Fund 2-3 agents on mainnet with small real capital ($50-200 USDC per agent)
  • Agents trading on mainnet with real funds -- demonstrating the mechanism works with real value at stake
  • Record a 3-minute demo video of agents trading in real-time with on-chain settlement confirmation
  • Prepare investor demo flow: open the app, show live agent offers, show a trade settling in under 2 seconds, pull up Solana Explorer showing the escrow transaction
  • Landing page at coin.family with pitch summary and link to live demo
Milestone: Working product demo on Solana mainnet with real funds. Investor-ready: show the app, show agents trading autonomously, execute a live trade, verify on-chain. Demo video recorded and landing page live.

4.1 Phase 1: Core Infrastructure (Weeks 5-8)

Phase 1 builds the foundational infrastructure that the MVP did not include: authentication, wallets, identity, and expanded token support. By the end of Phase 1, the full backend is operational on devnet with real user accounts.

1
Authentication via Privy
Integrate Privy for social login supporting X (Twitter), Farcaster, and email. Privy handles session management and JWT tokens. Users sign in with one tap -- no seed phrases, no MetaMask.
2
Embedded Wallets
Create embedded Solana wallets for humans via Privy (MPC or enclave-based key management). Create programmatic Solana keypairs for agents. Users never see private keys -- wallet is abstracted behind the auth layer. Recovery via Privy social login.
3
On-Chain Identity
SNS / Bonfida .sol domain registration during onboarding. Agent identity cNFTs minted via Metaplex Bubblegum (compressed NFTs). Each user gets a .sol domain and their agent gets a separate .sol domain (e.g., alice.sol and alice-agent.sol).
4
Expanded Token Support
Expand from SOL/USDC only (MVP) to all V1 listed tokens (14): SOL, JUP, PUMP, ZEC, HYPE, SKR, cbBTC, ETH, BONK, PENGU, RAY, EURC, JTO, PYTH. All tokens traded exclusively against USDC as the sole quote currency. New pairs added flexibly based on user requests and top Jupiter volume.
5
Backend Expansion
Convex schema expansion: users, agents, offers, trades, ratings, timeout_logs. Convex server functions for offers CRUD, trades, and user management (fully type-safe, no ORM). Convex real-time subscriptions for live offer updates pushed to all connected clients. Scale to 10-20 Coin-operated agents covering all V1 token pairs.

Phase 1 Deliverable: Full backend with wallet + identity + escrow + auth working on Solana devnet. 10-20 agents providing liquidity across all V1 token pairs.

4.2 Phase 2: Full Marketplace UI (Weeks 9-12)

Phase 2 builds the consumer-facing product: the marketplace interface, agent configuration wizard, reputation system, live trade feed, and tutorial mode. By the end of Phase 2, the exchange is fully functional on devnet with agents providing liquidity and humans trading.

1
Marketplace UI
Full marketplace interface with hybrid layout: order-book-style table on desktop, card-based feed on mobile. Token pair selector tabs, price range filtering, reputation filtering, sort by best price / highest reputation / newest / largest amount. Jupiter reference price displayed for every offer.
2
Buy/Sell Flows
Complete trade execution: wallet approval, escrow lock, 15-minute timeout, atomic settlement. Trade detail screen showing fee breakdown, Jupiter comparison ("X% better than Jupiter"), and post-settlement Solana Explorer link. Post Offer screen for sellers to create new offers.
3
Agent Configuration Wizard
After completing their first manual trade, users see: "You just saved $X vs Jupiter. Want an agent to do this 24/7?" Simple wizard: daily spending cap (USDC), per-trade limit, approved token pairs (checkboxes), auto-accept threshold (% better than Jupiter). No developer knowledge required.
4
Reputation System
Reputation scoring engine: R = 0.15T + 0.20V + 0.25S + 0.40C. Post-trade rating system (1-5 stars). Four verification tiers: Unverified, Verified, Trusted, Established. Social verification via X account age, follower count, verified badge; Farcaster Neynar score for Farcaster users. Anti-gaming protections.
5
Live Trade Feed + Tutorial Mode
Real-time feed of completed trades (token pair, amount, price, .sol domains, timestamp) powered by Convex real-time subscriptions. Social proof showing the platform is active. Tutorial agent / demo mode with fake USDC so new users can learn without risk -- critical for non-technical user onboarding (2AM's concept).

Phase 2 Deliverable: Fully functional exchange on Solana devnet with agents providing liquidity, marketplace UI, reputation system, agent configuration, and tutorial mode. Ready for internal testing.

4.3 Phase 3: Security, Beta & Launch (Weeks 13-16)

Phase 3 hardens the product for public launch: security review, geo-blocking, privacy features, performance optimization, mainnet migration, closed beta, and finally public launch with marketing push.

1
Security & Compliance
Security review via peer review + audited library patterns (formal audit deferred to V2). US geo-blocking via Vercel Edge Middleware + disclaimers. Wyoming DAO LLC filing if not already completed. Per-trade escrow caps at launch with progressive trust limits.
2
Privacy & Performance
Encrypted trade metadata (end-to-end). Profile visibility controls: trade as agent profile only, hiding human identity. Anonymous offer listing with .sol domain hidden until trade is initiated. Performance optimization: response caching, Helius RPC failover, Convex query optimization.
3
Mainnet Migration & Launch
Migrate full product from devnet to Solana mainnet. Deploy all Coin-operated agents on mainnet with funded wallets. Closed beta with 20-50 testers for 1-2 weeks. Bug fixes from beta feedback. UI/UX polish pass: animations, loading states, error handling, empty states, mobile responsiveness. Public launch + marketing push.

Phase 3 Deliverable: Public launch on Solana mainnet. Full product with auth, identity, marketplace, agents, reputation, privacy, and compliance. Open to all non-US users.

5. V2: Growth (3-6 Months Post-Launch)

V2 -- 3-6 Months Post-Launch

V2 transitions Coin from a validated product to a growth-stage platform. The central objectives are expanding distribution (native mobile apps, fiat onramping), opening the platform to third-party agents, adding order matching infrastructure for higher-frequency trading, and building the social features that drive organic acquisition. V2 begins only after V1 launch metrics are confirmed -- specifically, consistent daily GMV above $50K and at least 100 active human traders.

5.1 Features

1
Native iOS & Android Apps
React Native/Expo build leveraging the existing web codebase for maximum code reuse. Submitted to both App Store and Google Play.
  • Push notifications for trade confirmations, offer matches, agent activity, and price alerts
  • Biometric authentication (Face ID, Touch ID, fingerprint) for trade confirmation
  • Deep linking for sharing offers and profiles across social media
  • Offline-first architecture with local caching for offer browsing
  • Background agent status monitoring with persistent notification
2
Additional Social Integrations
Expand social verification beyond X and Farcaster to YouTube, GitHub, Instagram, and TikTok. Each platform contributes to the reputation score's social verification component (S).
  • GitHub: Verified developer identity -- critical for agent operators proving technical credibility
  • YouTube: Creator economy trust signal -- channel age, subscriber count, content history
  • Instagram: Real-world identity correlation for human traders
  • TikTok: Emerging crypto audience -- younger demographic trust signals
  • All integrations use OAuth2 -- no password storage, revocable at any time
3
Fiat Onramping via MoonPay / Transak
Fund wallets with fiat currency directly within the app. Apple Pay and Google Pay integration. Eliminates the need for users to already hold crypto -- zero to trading in under two minutes.
  • Apple Pay (iOS) and Google Pay (Android) for instant funding
  • Debit/credit card fallback for both platforms
  • Fiat to USDC conversion handled by MoonPay or Transak infrastructure
  • Dramatically reduces onboarding friction for non-crypto-native users
4
Third-Party Agent Marketplace
Open the platform to developer-built agents. Any developer can deploy a custom trading agent on Coin using standardized frameworks. Key transition from Coin-operated liquidity to community-driven liquidity.
  • ElizaOS plugin: Drop-in plugin for ElizaOS agents to connect to Coin's offer system
  • Solana Agent Kit template: Starter template for building Coin-native agents
  • Agent verification process: code review, testnet validation, spending cap requirements
  • Agent marketplace: searchable directory with reputation scores, strategies, and performance history
  • Revenue: third-party agents keep their spreads, pay the 0.15% per-side exchange fee + 0.05% platform fee
  • Virtuals integration for enhanced agent capabilities
5
Limit Orders & Partial Fills
Transition from manual-only offer selection to programmatic order matching. Large offers can be filled incrementally by multiple counterparties.
  • Automatic matching engine for offers meeting price/quantity criteria
  • Partial fills: buyers can take a portion of a large offer, not just full fill
  • Order types: Good-Til-Cancelled (GTC), Immediate-Or-Cancel (IOC), Fill-Or-Kill (FOK)
  • Matching is off-chain; settlement remains on-chain and atomic via escrow program
  • Manual offer selection still available for users who prefer the V1 browse-and-pick experience
6
Agent Analytics Dashboard
Comprehensive analytics for agent operators to monitor performance, optimize strategies, and track profitability.
  • PnL tracking per agent: realized/unrealized gains, fee costs, net revenue
  • Volume statistics: daily/weekly/monthly trends, pair breakdowns
  • Counterparty map: visualization of which agents/humans your agent trades with most
  • Spread analysis: historical spreads vs Jupiter benchmarks with performance attribution
  • Inventory management: real-time token balance tracking across all agent wallets
  • Exportable reports (CSV, PDF) for tax and compliance
7
Dynamic Agent Pricing
Upgrade from static offset pricing (V1) to dynamic pricing where agents adjust spreads based on real-time market conditions.
  • Volatility-aware: widen spreads during high volatility, tighten during calm markets
  • Volume-responsive: tighter spreads on high-volume pairs, wider on illiquid pairs
  • Inventory-driven: adjust prices to rebalance token holdings automatically
  • Available to both Coin-operated and third-party agents via configuration
8
Social & Retention Features
Features designed to drive organic acquisition and retention, championed by 2AM.
  • PnL Sharing: Users share daily/weekly/monthly/yearly earnings on X, Farcaster, and other socials -- organic marketing through flex culture
  • Referral Program: Users earn trading fee rebates for referring new traders. Tiered rewards based on referee's trading volume
  • Verified Checkmark Paid Tier: Premium verification for enhanced trust signaling. Higher trade limits, priority offer placement, blue checkmark badge. Monthly subscription in USDC
  • Creator Fees: Incentive mechanism for agents and humans -- retention through earning
9
Formal Smart Contract Audit
Commission a formal audit of the escrow program from a reputable Solana audit firm (OtterSec, Neodyme, or similar). Estimated cost: $30,000-$80,000. Justified by V1 revenue and TVL growth.
  • Full audit of escrow Anchor program: create_offer, accept_offer, cancel_offer, claim_timeout, fee management
  • Token handling review: SPL token transfers, PDA derivation, rent-exempt account management
  • Formal verification of critical paths (atomic swap logic)
  • Public audit report published for transparency

6. V3: Scale (6-12 Months Post-Launch)

V3 -- 6-12 Months Post-Launch

V3 transforms Coin from a growth-stage product into infrastructure capable of handling institutional volume and advanced trading patterns. The focus shifts from user acquisition to depth: multi-agent support, privacy via Light Protocol, streaming micropayments, institutional API access, and DEX aggregator integrations. V3 begins when V2 growth targets are sustained for at least 30 consecutive days.

6.1 Features

1
Multi-Agent Support
Users can own and operate multiple specialized agents, each with its own wallet, strategy, and identity. Enables sophisticated strategies requiring separation of concerns.
  • Agent types: market maker, arbitrageur, DCA bot, portfolio rebalancer, liquidation hunter
  • Per-agent wallets, configuration, and analytics -- fully isolated
  • Agent-to-agent communication within a user's fleet for coordinated strategies
  • Agent fleet dashboard: unified view of all agents' performance and positions
  • Up to 10 agents per user account (higher limits for Verified/Established tier users)
2
Privacy via Light Protocol
Evaluate and implement privacy-preserving settlement using Light Protocol or other Solana-native privacy solutions where trade amounts, counterparty identities, and token types are hidden from public view while remaining verifiable.
  • Evaluate Light Protocol for ZK compressed accounts on Solana
  • Selective disclosure: prove trade history for compliance without revealing details
  • ZK proofs for reputation verification -- prove tier status without revealing trade history
  • Privacy is opt-in: users choose between transparent and private settlement per trade
3
Streaming Micropayments
Sub-cent continuous payment flows for high-frequency agent-to-agent trading. Built on x402 payment channels, enabling real-time settlement without per-transaction gas costs.
  • Payment channels between frequently-trading agent pairs
  • Real-time settlement streams with periodic on-chain finalization
  • Ideal for high-frequency market making where agents update quotes every second
  • Fallback to standard escrow settlement if channel capacity exceeded
4
Institutional API
RESTful and WebSocket API for institutional agent operators managing large fleets and requiring programmatic access to the full exchange.
  • Bulk offer management: create, update, cancel hundreds of offers in a single API call
  • Programmatic trading via REST/WebSocket with sub-100ms response times
  • Webhook notifications for trade events, offer matches, settlement confirmations
  • Dedicated rate limits: 10,000 requests/minute for institutional tier
  • SLA guarantees: 99.9% uptime, <200ms P99 latency
  • API key management with IP whitelisting and per-key permissions
5
DEX Aggregator Integrations
Integrate with Jupiter aggregator so that when Coin's P2P offers provide better pricing than DEX pools, Jupiter routes trade flow through Coin. This is a critical growth lever.
  • Jupiter routing integration: Coin registered as a liquidity source for Solana token pairs
  • Jupiter queries Coin's offer book alongside AMM pools for optimal routing
  • Increases volume and visibility without requiring user acquisition spend
  • Coin agents effectively compete with Raydium/Orca pools on an equal footing
  • Additional aggregator integrations as they emerge on Solana
6
Cross-Platform Reputation Portability
Make Coin reputation scores verifiable and portable outside the platform using on-chain attestations.
  • On-chain reputation attestations verifiable by any smart contract or dApp on Solana
  • Bidirectional: import reputation from other Solana protocols
  • Use cases: DeFi protocols can gate access based on Coin reputation tier
  • Reputation becomes a composable primitive in the broader Solana ecosystem
7
Advanced Agent AI
Sophisticated AI-driven pricing and trading strategies for both Coin-operated and third-party agents.
  • Volatility-aware pricing: widen spreads during high volatility, tighten during calm markets
  • Volume-predictive algorithms: anticipate demand surges and pre-position inventory
  • Cross-pair correlation analysis: price SOL/USDC offers based on correlated pairs (JitoSOL, mSOL)
  • Machine learning models for optimal spread calculation trained on historical trade data
  • Strategy backtesting framework: test strategies against historical data before deployment
8
Tweet-Based Transactions
X (Twitter) integration enabling users to initiate and complete P2P trades via tweet commands. Brings Coin's exchange to where crypto conversations already happen.
  • Command format: @coin_exchange sell 10 SOL for 1350 USDC
  • Bot responds with offer link and confirmation details
  • Counterparties can accept offers via reply or direct link
  • Social trading feed: public offer activity visible on Coin's X account
  • Requires linked X account with Coin profile for authentication
9
Data Layer Strategy
Agent trading data as a valuable asset for AI model training and market intelligence -- dEXploarer's vision for long-term value creation.
  • Anonymized, aggregated trading data available via API for research and ML training
  • Market microstructure insights: spread dynamics, agent behavior patterns, liquidity flows
  • Data partnerships with AI research institutions and trading firms
  • Privacy-preserving data sharing: aggregate insights without exposing individual trades

7. V4+: Ecosystem (12+ Months Post-Launch)

V4+ -- 12+ Months Post-Launch

V4 and beyond transition Coin from a standalone product to an open ecosystem and protocol layer. The platform becomes infrastructure that other applications build on. Token launch, governance, multi-chain expansion, and enterprise features are all contingent on proven product-market fit and sustainable revenue. Nothing in V4+ is guaranteed -- each feature is evaluated against demonstrated demand and strategic value at the time of implementation.

7.1 Features

1
Multi-Chain Expansion
Evaluate expansion beyond Solana to other high-activity chains, but only if demonstrated user demand exists. Solana remains the primary chain.
  • Candidate chains: Base (Coinbase ecosystem), Ethereum mainnet (institutional liquidity), Arbitrum (DeFi depth)
  • Evaluation criteria: minimum 1,000 user requests, clear agent operator demand, strategic partnership
  • Cross-chain settlement: evaluate Wormhole bridge infrastructure vs chain-native escrow contracts
  • Risk: multi-chain fragments liquidity -- only expand if net positive for total GMV
2
Yield & Savings Features
Passive earning products built on top of the P2P exchange. Users deposit tokens and earn yield generated by agent market-making activity.
  • Agent-powered yield vaults: deposit USDC, agents trade on your behalf, withdraw principal + earnings
  • Tiered risk/return profiles: conservative (low spread, high volume), aggressive (wider spread, higher risk)
  • Transparent performance history and fee structure
  • Non-custodial: user retains control of funds via smart contract
3
Token Launch (Post-PMF Only)
If and when appropriate, launch a COIN token with clear utility. This is not a fundraising mechanism -- only justified with proven PMF, established revenue, and specific token utility.
  • Governance: Token holders vote on reputation weights, listing criteria, fee adjustments, protocol upgrades
  • Staking: Stake COIN to reduce exchange fees (0.3% to 0.2% for stakers)
  • Fee Distribution: Portion of exchange fee revenue distributed to stakers
  • No token launch before $5M daily GMV and 6+ months of positive unit economics
  • Token distribution: community allocation > team allocation, with multi-year vesting
4
Governance System
Decentralized governance for protocol-level decisions. Transitions Coin from team-controlled parameters to community-governed infrastructure.
  • Reputation weight governance: community votes on T, V, S, C coefficient values
  • Token listing governance: community proposals and votes for adding/removing tokens
  • Fee adjustment governance: community can propose and vote on fee changes
  • Protocol upgrade governance: major feature releases require community approval
  • Tiered voting power based on COIN stake + reputation score + account age
5
Developer SDK
Open SDK enabling any developer to embed Coin's P2P exchange functionality into their own applications. Coin becomes infrastructure, not just a destination.
  • TypeScript SDK for web and Node.js applications
  • React component library for embeddable trading widgets
  • White-label exchange components: offer feed, trade flow, wallet management
  • Plugin system for custom agent behaviors and strategies
  • Revenue share: SDK integrations generate exchange fees split with the integrating app
6
Enterprise & Institutional Features
Dedicated tooling for institutional operators managing large-scale agent fleets and trading operations.
  • Dedicated agent fleets with centralized management console
  • Compliance tools: transaction monitoring, suspicious activity reporting, audit trails
  • SLA guarantees: 99.99% uptime, dedicated support channel, priority incident response
  • Custom reporting: regulatory compliance reports, tax documentation, portfolio attribution
7
Desktop App
Professional-grade desktop trading application for power users and institutional traders who need more screen real estate and advanced tooling.
  • Multi-monitor support: detachable panels for offer book, charts, analytics, and agent management
  • Advanced charting: candlestick charts, depth charts, spread visualization
  • Keyboard shortcuts for rapid trade execution and offer management
  • Built with Tauri for cross-platform compatibility (macOS first, then Windows/Linux)
8
Custom x402 Facilitator
Build Coin's own x402 facilitator to reduce dependency on external infrastructure and gain control over settlement fees, routing, and compliance.
  • Lower per-transaction fees by eliminating third-party facilitator margin
  • Custom settlement logic optimized for Coin's specific use cases on Solana
  • Direct integration with Coin's escrow programs for reduced latency
  • Maintain backward compatibility with existing x402 facilitators as fallback
